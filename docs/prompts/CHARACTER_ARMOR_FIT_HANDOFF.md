## The garment pipeline (what exists)

`art_source/characters/build_jacket_part.py` processes the first garment
(Meshy-generated jacket, source sha-pinned in
`art_source/imported/jacket_default/`) into
`assets/characters/parts/top_jacket_cozy.glb`. Stages, in order:

1. Import GLB, 60° smooth-by-angle shading (keep generated topology crisp —
   do NOT subdivide/decimate it into blobs).
2. Per-axis fit: sleeves to wrist (SLEEVE_END_X 0.28), torso half-width
   0.123, back 0.097 / front 0.107 clearance, hem −0.128 to collar 0.128,
   sleeve shear ramps cuff centers onto the arm line (z 0.093), hem flared
   +10% so striding thighs never punch through.
3. Region materials by geometric rules: mustard body, cream collar ring
   (back/sides of neck only — no cream on the chest) + cuffs, walnut
   buttons. Flat palette-hex colors; no textures.
4. Weight rig (every step below exists because its absence produced a
   visible bug):
   - `rig.data.pose_position = "REST"` **before** Data Transfer — the master
     file keeps the idle pose applied and sampling the posed body gives
     sleeves leg/foot weights (frozen sleeves + exploding hem).
   - Data Transfer POLYINTERP_NEAREST from `PlayerMaleBody`, then a
     nearest-vertex kd-tree fallback for any vertex under 0.05 total weight
     (weightless vertices collapse to the origin in Godot, invisibly fine in
     Blender).
   - `vertex_group_smooth` ×4 (per-vertex sampling leaves discontinuities →
     spikes when posed).
   - Strip leg/foot/toe groups entirely and renormalize (a jacket hangs from
     the torso; leg influences make the hem ride the stride), with a hips
     fallback for any vertex left weightless.
   - `vertex_group_limit_total(4)` + `normalize_all` (glTF exports 4
     influences).
   - Armature modifier **and** `jacket.parent = rig` — without the object
     parenting the glTF skin exports in the wrong space and the garment
     explodes when posed.
5. Export GLB: selection = garment + rig, `export_skins=True`,
   `export_animations=False`, `export_apply=True`.
6. Runtime: `CharacterAssembler._equip_skinned_part` parents meshes
   **directly under the live Skeleton3D** with `skeleton = NodePath("..")`
   set **before** `add_child` — Godot resolves the skin at ENTER_TREE and a
   path corrected afterwards is not reliably re-resolved.
